# Границы прототипа

| Область | Реализовано | Ограничение / следующий шаг |
|---|---|---|
| Проверка решений | Python 3.12 и C++17, настоящие Docker-контейнеры, OK/WA/CE/RE/TLE/MLE | Нет интерактивных задач и пользовательских чекеров |
| Контесты | Создание задач с тестами, эталон, публикация, согласие, регистрация, арена, ICPC/IOI, таблица | Нет заморозки таблицы и дорешивания |
| Дуэли | Ссылка, два подтверждения готовности, отсчёт, серверный дедлайн, прогресс, сдача и протокол | Нет быстрого подбора, Elo-пересчёта и реванша одним действием; показанные 1200 — начальный рейтинг |
| Команды | Два участника, приглашение, регистрация капитаном, метки задач, общий зачёт, живой код напарника, чат | Нет режима 2×2 и эстафеты |
| Вклад | Отправки, OK, задачи и размер текущих черновиков каждого | Нет точной атрибуции символов в итоговом коде; счётчик символов не выдаётся за авторство |
| Запись | Снимки редактора, вставки, фокус, отправки, нумерация событий, SHA-256, восстановление и просмотр | Сохраняются снимки, а не компактные Monaco-дельты; HTTP-события сериализованы, уведомления идут по Socket.IO |
| Обрыв | Дедлайн не останавливается; подтверждённый черновик в БД, очередь событий живой вкладки досылается | Закрытие вкладки до подтверждения автосохранения может потерять последние секунды. Нет устойчивого IndexedDB outbox |
| Сигналы | EXTERNAL_PASTE, AWAY_THEN_SOLVE, LONG_AWAY как контекст, NO_RECORDING, CODE_NOT_FROM_EDITOR, сходство | Автоматические INHUMAN_TYPING, TOO_FAST_SOLVE и SHARED_DEVICE не реализованы. Сигнал скорости в seed — синтетический пример, не работающий детектор |
| Сходство | Нормализация, k-граммы, winnowing, Жаккар, пара кодов и время первой отправки | Регулярные выражения, не полный AST. Короткие независимые решения часто похожи; окончательное решение за человеком |
| Приватность | Нет камеры, микрофона и записи экрана; доступ по ролям; удаление записей после 30 дней | Перепечатывание с телефона не выявляется. Согласие в демо не заменяет юридическую политику реального оператора |
| Идентичность | Bcrypt, httpOnly JWT-cookie, роли, регистрация | Демо-кнопки намеренно позволяют войти без пароля; нет подтверждения email, OAuth и восстановления пароля |
| Демонстрационные данные | Задачи, участники, команда, контесты, примеры записей | Исторические отправки и нарушения сгенерированы seed и помечены. Это не реальные инциденты и не результаты запуска всех исторических решений |
| Производительность | Отдельная очередь, лимит отправок, масштабируемые воркеры, Redis adapter | VDS 2 vCPU / 4 ГБ: один judge-слот. 100 дуэлей не проверялись нагрузкой, расчёт 8 слотов — оценка |
| Изоляция | Нет сети, root filesystem read-only, nobody, drop capabilities, no-new-privileges, лимиты, защита чтения /proc харнесса | Docker использует ядро хоста; socket у доверенного воркера даёт привилегированный доступ. Нет gVisor / microVM |
| Метрики sandbox | CPU и ru_maxrss из Linux, watchdog и удаление контейнера | ru_maxrss — максимум дочерних процессов харнесса, не точная пиковая память каждого отдельного теста. Компиляция C++ влияет на максимум |
| Интерфейс | Адаптивная вёрстка, локальные IBM Plex с кириллицей, Monaco и простой редактор | На маленьком экране блоки идут последовательно; сложное программирование удобнее на ноутбуке |

Обязательные сценарии S1–S6 реализованы настоящими сервисами. Имитации относятся к демо-идентичности и подготовленным историческим данным, а не к текущим вердиктам или действиям кнопок. Фактические результаты прогонов перечислены в STATUS.


## Ответ на вопрос о выходе из контейнера

Риск существует. Код участника не получает Docker socket или production.env; сокет доступен доверенному judge-воркеру. Но все контейнеры используют ядро хоста. Уязвимость ядра/runtime или компрометация воркера с сокетом может затронуть весь VDS. Текущие запреты сети, nobody, read-only, cap-drop, no-new-privileges и лимиты не доказывают отсутствие escape.

Для публичного выполнения недоверенного кода нужны отдельный judge-хост без секретов приложения и усиленный runtime (gVisor/microVM), обновления и повторная проверка совместимости. Это пока не внедрено. Источники: [Docker security](https://docs.docker.com/engine/security/), [gVisor](https://gvisor.dev/docs/), проверены 07.11.2026. Проверки вредных примеров подтверждают конкретные ограничения, но не абсолютную изоляцию.
