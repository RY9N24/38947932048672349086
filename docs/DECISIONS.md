# Решения реализации

1. **Стек сохранён:** Next 15, React 19, Nest 11, Prisma/PostgreSQL, Redis/BullMQ, Socket.IO, Docker judge. Обработчики API разделены на auth / competition / integrity; Nest обслуживает HTTP, Zod валидирует запросы.
2. **Версии закреплены lockfile.** Production — Node 22. Windows-разработка ведётся нативно, PostgreSQL/Redis и песочницы — в Docker Desktop Linux.
3. **Шрифты взяты у IBM, не из устаревшего Google-пакета.** Condensed в старом пакете не содержал русских букв. Подключение полных локальных WOFF2 через next/font; детали в FONTS.
4. **Запись — снимки кода.** Для хакатона проще надёжно восстановить состояние. Полные дельты и сжатие — следующий шаг. События идут через сериализованный HTTP, Socket.IO уведомляет о смене состояния и вердиктах.
5. **Статусы вычисляются из серверных дедлайнов.** Это переживает рестарты без отдельного cron завершения каждого матча. Готовность и приём приглашений защищены транзакциями и блокировками.
6. **Docker stdin передаётся явным HTTP Upgrade с пустым телом.** Автоматический attach в используемом сочетании dockerode/modem/Node иногда добавлял JSON параметров запроса в stdin контейнера. Регрессия проявлялась в параллельном тесте. Dockerode по-прежнему создаёт, запускает, ограничивает и удаляет контейнеры; транспорт attach реализован явно.
7. **Хэширование канонического JSON.** PostgreSQL JSONB переставляет ключи; обычный JSON.stringify делал проверку цепочки ложно отрицательной.
8. **Один judge-слот на VDS.** Новый сервер имеет 2 vCPU и 4 ГБ; локальная сборка переносится готовыми образами. Нет обещания выдержать 100 дуэлей на этой машине.
9. **Презентация строится скриптом в файлы.** Это прямое требование задания: редактируемый PPTX и PDF, а не облачная ссылка. Публикация в Spaces вместо локальных файлов не применяется.
10. **Изоляция не отключается при ошибке.** Недоступный Docker даёт SE. Никакого исполнения кода в API-процессе или на хосте.
