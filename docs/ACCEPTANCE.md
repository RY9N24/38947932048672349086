# Приёмка перед показом

Проверять на целевом URL в чистом профиле. Для двух людей нужны два независимых браузерных контекста, не две вкладки одного профиля.

## S1 — задача и контест

1. `/login` → «Организатор». Судейская → «Добавить задачу». Форма уже заполнена примером «Квадрат числа» и тремя тестами.
2. «Сохранить задачу» → в строке задачи «Проверить эталоном» → вставить `demo/square_ok.py` → «Запустить проверку» → OK на всех трёх тестах.
3. «Создать контест»: название, выбрать задачу, начало текущее или на минуту раньше, длительность 60, «Опубликовать контест».
4. В другом профиле войти как Иван, открыть Контесты → созданный контест → «Согласие на запись», прочитать, поставить «Понятно, участвую», подтвердить. Должна появиться кнопка «Войти на арену».

## S2 — разные вердикты и таблица

1. Для готовой «Разминки» использовать `demo/wa.py` → WA (тест 2), затем `demo/ok.py` → OK. Для нового «Квадрата» — неправильный `print(4)` и `demo/square_ok.py`.
2. Между отправками 5 секунд; кнопка временно блокируется.
3. Во втором профиле открыть протокол того же контеста. После OK результат меняется сам.

## S3 — дуэль

1. Иван → Дуэли → «Создать дуэль». Скопировать ссылку сопернику.
2. Анна в другом профиле открывает ссылку, «Принять вызов». Оба дают согласие и нажимают «Готов к раунду».
3. Дождаться отсчёта. Иван отправляет `demo/ok.py` на A. У Анны меняются счёт и прогресс.
4. Анна пишет черновик; дождаться «Изменения сохранены». Перезагрузить вкладку: код восстановлен, время не прибавилось.
5. Анна → «Сдаться» → подтверждение. Протокол показывает победителя, результаты и SHA-256.

## S4 — команда

Быстрый показ: Дарья и Михаил уже в «Двух переменных», записаны в «Парный зачёт».

Полный путь: Иван создаёт новую команду, Анна принимает ссылку. Оба открывают «Парный зачёт» и дают согласие. Капитан выбирает команду и нажимает «Записать команду».

На арене «Взять задачу» → напарник видит метку. Написать код → напарник открывает «Код напарника». Отправить решение → общий OK. Отправить сообщение в переговорной. Открыть протокол — строка команды. В блоке напарника видны попытки и OK каждого.

## S5 — проверка

1. Организатор → Видеоповторы → Сергей Климов / «Отборочный тур». На экране явно написано, что это демонстрационная запись.
2. «К моменту» у внешней вставки → появился большой фрагмент. Запустить/приостановить повтор, передвинуть ползунок, сменить скорость.
3. «Проверить целостность записи» → цепочка цела.
4. Ольга Белова → «Похожие решения» → раскрыть пару, увидеть код Ольги и Олега, процент и первого отправившего, перейти к записи второго.
5. Выбрать «Дисквалифицировать», написать причину, подтвердить. В протоколе организатора участник зачёркнут. Участникам он не выдаётся в таблице. После показа вернуть «Нарушений не обнаружено», если это только тест.
6. Участник открывает «Мои записи» и видит только своё. Прямой запрос чужого повтора должен вернуть 403.

## S6 — небезопасный код

Через арену отправить `tle.py`, `write_fs.py`, `net.py`, `read_etc_passwd.py`, `mle.py`, `ce.cpp`. Не запускать эти файлы на хосте. Проверить ожидаемые TLE/RE/MLE/CE и сразу отправить `ok.py`: снова OK, сайт отвечает.

Для очереди: `scripts/test-queue.ts` создаёт 20 одновременных TLE-заданий и одно нормальное, регулярно проверяет `/api/health`, затем удаляет только свои тестовые отправки. Запускать с корректными DATABASE_URL и REDIS_URL только на демонстрационной БД.

## Дополнительные проверки

- `pnpm test`: подсчёт ICPC/IOI, ветки победителя, канонические хэши, сходство.
- `pnpm typecheck`; `pnpm test:judge`; `pnpm test:e2e`.
- `docs/screens/axe-report.json` должен быть `[]`. Снимки экранов — пять размеров; визуально проверить новые состояния после правок.
- Перезапуск API и judge посреди дуэли: дедлайн не сбрасывается, сохранённый код восстанавливается, очередь не теряется.
- Убедиться, что презентация, видео и речь открываются **до** выступления. Показ не должен зависеть от сети.
